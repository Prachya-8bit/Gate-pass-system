# Gate Pass → epro Sync (สคริปต์กรอกข้อมูลอัตโนมัติ)

สคริปต์นี้ทำงานแทนคน: log-in เข้า `eprocurement.syssteel.com` ด้วยบัญชีของคุณ ขอใบงานจากระบบ Gate Pass แล้วกรอกลงฟอร์ม `reg/FrmWorker.aspx` ทีละใบ

การกันส่งซ้ำอยู่ที่ **ฝั่ง server** ไม่ใช่ไฟล์ในเครื่อง: สคริปต์ยิง `POST /api/integration/claim` เพื่อ "จอง" ใบงาน (compare-and-set สถานะเป็น `SYNCING`) แล้วรายงานผลกลับด้วย `POST /api/integration/report` รันซ้ำหรือรันสองเครื่องพร้อมกันก็ไม่กรอกซ้ำ รายละเอียดใน [docs/sync-state-machine.md](../docs/sync-state-machine.md)

> ⚠️ ทุกรายการที่สคริปต์กรอก ระบบ epro จะบันทึกในชื่อบัญชีของคุณ **และลบจากฝั่งเราไม่ได้** (epro ไม่มี API) ตรวจ dry-run ให้มั่นใจก่อนรันจริงเสมอ

## ติดตั้งครั้งแรก

```bash
cd automation
npm install
npx playwright install chromium
cp .env.example .env        # แล้วเปิดแก้ กรอก username/password ของ epro
```

Selector ของ login และฟอร์ม `FrmWorker.aspx` ใส่ครบแล้วใน `selectors.mjs` — ถ้าช่องไหนยังเป็น `'#TODO'` สคริปต์จะไม่ยอมรันและบอกว่าขาดตัวไหน (เก็บหน้าใหม่ด้วย `npm run capture` ด้านล่าง)

การจับคู่ข้อมูล: **ฝั่ง server เป็นคนจัดกลุ่ม** — record ที่บริษัท + ช่วงวันที่ + โซนเดียวกันถูกรวมเป็นใบงานเดียว (`groupKey()` ใน `lib/sync.ts`) แล้วส่งมาให้สคริปต์เป็นก้อน สคริปต์เพิ่มคนงานทีละคนด้วยปุ่ม "เพิ่ม" ของฟอร์ม ค่าที่ต้องเลือกเอง (Plant, ผู้อนุมัติ, เบอร์ผู้ขอ) ตั้งใน `.env`

## การใช้งาน

```bash
# 1) เปิด Gate Pass dev server ทิ้งไว้ (อีก terminal หนึ่ง ที่โฟลเดอร์หลัก)
npm run dev

# 2) ทดสอบแบบไม่กด submit — กรอกรายการแรกให้ดูเฉย ๆ
npm run sync:dry

# 3) รันจริง
npm run sync
```

- Browser จะเปิดขึ้นมาให้เห็นทุกขั้นตอน (ไม่ใช่เบื้องหลัง) — ดูมันทำงานได้เลย ตั้ง `HEADLESS=true` เมื่อรันใน cron
- ถ้าใบงานไหนพัง สคริปต์เซฟภาพหน้าจอไว้ที่ `screenshots/` รายงานผลกลับ **แล้วไปทำใบต่อไป** (ไม่หยุดทั้งรอบ) ใบที่พังจะถูกจัดเป็น `ไม่สำเร็จ` (retry ได้) หรือ `ต้องตรวจสอบ` (ต้องมีคนไปเช็คใน epro) ตามว่าพังก่อนหรือหลังกด submit
- ถ้า `/claim` ตอบ 5xx (DB ไม่พร้อมชั่วคราว) สคริปต์ข้ามรอบนั้นแล้วจบปกติ — cron รอบหน้าเอาต่อ
- อยากให้รันเองทุกวัน: ตั้ง Windows Task Scheduler เรียก `run-sync.ps1` (มี `flock`/lock กันรันซ้อน) — แนะนำให้รันเองช่วงแรกจนมั่นใจก่อน

## ส่งคำขอนำรถเข้าโรงงาน (`epro-sync-vehicle.mjs`)

สคริปต์แยกไฟล์ ส่งคำขอลงฟอร์ม `reg/FrmOperation.aspx` (เมนู ยานพาหนะ → ปฏิบัติงานในโรงงาน) ทีละใบ 1 คำขอ = 1 คัน ไม่มีปุ่ม "เพิ่ม" เพราะห้ามมีผู้โดยสาร

```bash
cd automation
npm run sync:vehicle:dry   # กรอกใบแรกให้ดู ค้างหน้า 90 วินาที ไม่กด Save
npm run sync:vehicle       # รันจริง
```

ใช้ env เดิมทั้งหมด (`EPRO_PLANT`/`EPRO_APPROVER`/`EPRO_REQ_TEL`) เพราะ dropdown Plant และผู้อนุมัติของฟอร์มนี้เหมือนฟอร์มคนงานเป๊ะ — **ไม่ต้องตั้งค่าใหม่**

### สิ่งที่ต่างจากฝั่งคนงาน และเหตุผล

**1. ตรวจเวลาก่อนกรอก (pre-flight)** — epro บังคับว่าเวลาเริ่มต้องห่างจาก**ตอนกด Save** อย่างน้อย 1 ชั่วโมง แต่ pipeline ของเราคือ ผู้รับเหมากรอก → admin ยืนยัน (นานเท่าไหร่ก็ได้) → cron 15 นาที → ส่ง ถ้าเวลาเหลือน้อยกว่า 1 ชม.แล้ว สคริปต์**ไม่ส่งเลย** และรายงานเป็น `failed` + `permanent` เพื่อตัด auto-retry (retry ยิ่งแย่เพราะเวลาเดินหน้า) แล้วโผล่ในแถบเตือนแดงหน้า admin ให้คนไปจัดการ

**2. ดัก dialog หลังกด Save** — สคริปต์ accept dialog อัตโนมัติ ถ้าไม่ดักไว้ alert เตือน validation จะถูกกด OK แล้วสคริปต์รายงาน `ok` → แถวกลายเป็น "ส่งแล้ว" ทั้งที่ epro ไม่ได้บันทึกอะไร ตอนนี้ถ้ามี dialog โผล่หลัง submit จะถือว่า validation ไม่ผ่าน

**3. แยก error ด้วย "กด Save ไปแล้วหรือยัง" ไม่ใช่ข้อความ error** — พังก่อน Save = ไม่มีอะไรถูกบันทึก ลองใหม่ได้ (`failed`) · พังหลัง Save = ผลไม่แน่นอน ต้องให้คนไปเช็คใน epro (`unknown` → ต้องตรวจสอบ) **ห้ามเป็น `failed`** เพราะ `failed` retry ได้ = เสี่ยงส่งซ้ำ

**4. จังหวัดต้องห่อด้วย non-breaking space** — value ของ `ddlProvience` ใน epro คือ `" ระยอง "` ไม่ใช่ `"ระยอง"` DB เก็บชื่อสะอาด สคริปต์ห่อกลับด้วย `eproProvinceValue()` ใน `selectors.mjs`

**5. นาทีเลือกได้แค่ 00/15/30/45** — dropdown นาทีของ epro มี 59 ตัวเลือกไม่ใช่ 60 **ขาดค่า "10"** ฟอร์มฝั่งเราจึงจำกัดเป็นราย 15 นาทีเพื่อเลี่ยง

### ยังไม่ได้ต่อเข้า cron — ตั้งใจ

`run-sync.sh` / `run-sync.ps1` ยัง**ไม่**เรียก `sync:vehicle` เพราะใบที่เข้า epro แล้วลบจากฝั่งเราไม่ได้ ให้ส่งจริงใบแรกด้วยมือแบบเฝ้าดูหน้าจอ แล้วเปิดหน้ารายการใน epro ยืนยันว่าเข้าจริงก่อน

เมื่อมั่นใจแล้วค่อยเพิ่มใน `run-sync.sh` โดยให้รถรัน**ทีหลัง**คนงาน เพื่อไม่ให้ปัญหาฝั่งรถหน่วง sync คนงาน:

```bash
HEADLESS=true /usr/bin/npm run sync         >>"$LOG" 2>&1; rc1=$?
HEADLESS=true /usr/bin/npm run sync:vehicle >>"$LOG" 2>&1; rc2=$?
exit $(( rc1 != 0 ? rc1 : rc2 ))
```

⚠️ ใช้ **flock เดิมตัวเดียว** ห้ามเพิ่ม cron entry แยก — lock มีอยู่เพื่อกันไม่ให้มี browser สองตัว login บัญชี epro เดียวกันพร้อมกัน ถ้าแยก entry จะได้ session ชนกัน หรือถ้าแชร์ lock รถจะถูก skip เกือบทุกรอบแบบเงียบ
⚠️ ผลข้างเคียงที่ต้องรับ: **login epro 2 ครั้งต่อรอบ** ถ้าเจอ lockout ให้รวมสองสคริปต์ให้แชร์ browser context เดียว

## เก็บหน้าฟอร์มใหม่จาก epro (`capture-page.mjs`)

ใช้ตอนจะรองรับฟอร์มใหม่ หรือตอน epro เปลี่ยนหน้าเว็บแล้ว selector เดิมพัง — ต้องรันจากเครื่องที่เข้า epro ได้

```bash
cd automation

# 1) ดูรายการเมนูซ้ายทั้งหมดก่อน (กาง TreeView ให้เอง)
npm run capture:menu

# 2) เก็บหน้าฟอร์มที่ต้องการ — หาจากข้อความในเมนู
npm run capture -- --menu "นำรถยนต์" --name FrmVehicle

# หรือถ้ารู้ URL อยู่แล้ว
npm run capture -- --url https://eprocurement.syssteel.com/reg/FrmWorker.aspx --name FrmWorker
```

ได้อะไรมา (ลงโฟลเดอร์ `pages/`):

| ไฟล์ | ใช้ทำอะไร |
|---|---|
| `menu.json` | รายการเมนูทั้งหมด + `href`/`onclick` — บอกว่าเมนูเป็นลิงก์ปกติหรือ `__doPostBack` |
| `<name>.html` | DOM หลัง render ทั้งหน้า |
| `<name>.png` | ภาพเต็มหน้า |
| `<name>.controls.json` | **ตัวสำคัญ** — ทุก `ctl00_MainBody_*` พร้อม tag/type/maxlength และ **option ครบทุก dropdown** + validator ที่บอกว่า epro บังคับช่องไหน |
| `<name>.directurl.json` | ผลทดสอบว่าเปิด URL ตรงได้ไหม (ทดสอบใน browser context ใหม่ที่ไม่มี cookie เดิม) |

จากนั้นเอา `id` ใน `.controls.json` ไปเติมใน `selectors.mjs` และเอา option list ของ dropdown ไปใส่ในเว็บให้ตรง**ทุกตัวอักษร** ไม่งั้น `selectOption({ label })` จะ throw ทุกครั้ง

> ⚠️ ไฟล์ใน `pages/` มีชื่อ-เลขบัตรจริงของคนในระบบ — gitignore ไว้แล้ว **ห้าม commit ห้ามส่งออกนอกองค์กร**

**2 อย่างที่สคริปต์บอกแทนไม่ได้ ต้องดูด้วยตา:**
1. **รูปแบบวันที่** — พิมพ์วันที่ลงช่องดู แล้วอ่านค่าที่มันแสดงกลับว่าเป็น **พ.ศ. (2569)** หรือ **ค.ศ. (2026)** ฟอร์มคนงานใช้ ค.ศ. แต่ฟอร์มอื่นอาจไม่เหมือน — **ผิดปีจะไม่ error แต่ข้อมูลผิด 543 ปี**
2. **มีปุ่ม "เพิ่ม" ที่ต้องกดให้รายการขึ้นตารางก่อน Save ไหม** (ฟอร์มคนงานมี — `btnAddNewVisitor` + `dgVisitor`)

## ข้อจำกัดที่รู้ไว้

- ถ้า epro เปลี่ยนหน้าเว็บ ต้องอัปเดต `selectors.mjs` ตาม
- ถ้าหน้า login มี CAPTCHA/OTP สคริปต์จะผ่านไม่ได้ — ต้องคุยทางอื่น
- ต้องรันจากเครื่องที่เข้าถึง epro ได้ (ในเครือข่ายบริษัท/VPN)
